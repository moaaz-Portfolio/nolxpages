# ISEF research readiness checklist

NOLX Open Lab currently demonstrates a workflow; a working application by itself does not establish a research contribution.

Before presenting it as an ISEF research project:

1. State one narrow problem and a testable research question.
2. Review existing visual website builders and relevant research; identify the specific gap rather than claiming the idea has never existed.
3. Explain the technical contribution that is new in this project. A new color scheme or a collection of pages is not a research contribution.
4. Define measurable outcomes before testing (for example task completion time, number of editing errors, export success rate, or responsive-layout failures).
5. Compare against a meaningful baseline using the same tasks and conditions. Record trials, failures, and uncertainty; do not invent or selectively report results.
6. If people will participate in a study, check the current ISEF human-participant rules and obtain any required review/approval **before** collecting data.
7. Keep dated source-code versions, test cases, raw results, and a clear record of what the student personally designed and implemented.
8. Verify all third-party asset licenses and choose a formal license for original source code before calling the project open source.

Do not describe the software as AI-powered, fully accessible, secure, or experimentally validated unless those claims are implemented and supported by tests.
